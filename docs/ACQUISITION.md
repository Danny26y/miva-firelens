# Real input acquisition and provenance

Verified 2026-11-14: NASA's official [Archive Download](https://firms.modaps.eosdis.nasa.gov/download/)
offers historical active-fire CSV downloads and links to
[yearly country CSV archives](https://firms.modaps.eosdis.nasa.gov/country/).
The historical request interface supports Earthdata/email authentication.
Offline processing in this repository requires neither login nor a MAP_KEY.
No FIRMS observation CSV was downloaded as part of this implementation.

1. Open the country archive and select Nigeria, MODIS Collection 6.1, and
   VIIRS Suomi-NPP 375 m. Choose the same complete overlapping years for both
   products. If the country archive cannot supply the required interval, use
   Archive Download, choose Nigeria/region, those products, dates, and CSV.
   Follow the live NASA interface for authentication/request delivery.
2. Prefer the standard science-quality historical archive for a reproducible
   pitch dataset. NASA states NRT observations are replaced by standard-quality
   data as available, approximately five months later. Do not quietly mix NRT
   and historical quality. Record the actual version and date range received.
3. Extract downloaded archives locally. Preserve original CSVs unchanged outside
   the two canonical inputs, and keep NASA metadata/citation alongside them.
   For multiple years of one product, concatenate in date order with exactly
   one header after confirming identical columns, no overlapping dates, and no
   repeated rows. These aggregate counts intentionally retain every input row.
4. Save each product's CSV as exactly:
   `data/raw/modis_c61_nigeria.csv` and
   `data/raw/viirs_snpp_375m_nigeria.csv`.
   Confirm the VIIRS satellite is Suomi-NPP rather than NOAA-20/21, and that
   MODIS is Collection 6.1. Retain acquisition date, selected coverage interval,
   product, collection, original filename, source page/request and SHA-256 in a
   local provenance note. Neither filenames nor sparse detection dates prove
   complete temporal or nationwide coverage.
5. Run the README commands. Check `manifest.json`, counts, input hashes and
   date ranges before the UI loads the exports. A failed command leaves older
   exports unchanged; never interpret those as freshly processed results.

Do not guess direct file URLs: use links generated by NASA's live archive.
Availability and downloadable years can change. Include NASA's product citation
and acknowledgement delivered with your download in the pitch/data credits.

## Actual Kaduna state boundary (included)

The checked-in `data/boundaries/nigeria_adm1.geojson` is the full-resolution
Nigeria ADM1 FeatureCollection downloaded from the `gjDownloadURL` returned by
the verified [geoBoundaries NGA ADM1 metadata endpoint](https://www.geoboundaries.org/api/current/gbOpen/NGA/ADM1/).
`source_metadata.json` preserves that response. It identifies boundary ID
`NGA-ADM1-27671186`, source GRID3, reference year 2022, and CC BY 4.0 license.
The pinned actual download is:
[geoBoundaries Nigeria ADM1 at 9469f09](https://github.com/wmgeolab/geoBoundaries/raw/9469f09/releaseData/gbOpen/NGA/ADM1/geoBoundaries-NGA-ADM1.geojson).
Attribution: GRID3 Nigeria state boundaries, distributed by
[geoBoundaries](https://www.geoboundaries.org/), CC BY 4.0.
Keep the attribution in any UI or distributed dataset using this boundary.
The pipeline selects the feature named Kaduna; it never creates a bounding box.

To refresh deliberately in PowerShell (network access needed):

```powershell
$metadata = Invoke-RestMethod 'https://www.geoboundaries.org/api/current/gbOpen/NGA/ADM1/'
$metadata | ConvertTo-Json -Depth 20 | Set-Content -Encoding utf8 data/boundaries/source_metadata.json
Invoke-WebRequest -Uri $metadata.gjDownloadURL -OutFile data/boundaries/nigeria_adm1.geojson
```

A refresh may change geometry. Review source/license/year and run tests; retain
the metadata and hashes for reproducibility. NASA CSV downloads remain the
operator's next required action.
